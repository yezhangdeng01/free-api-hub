模型别名

把不同平台上的同一模型归并成一个别名，请求别名时组内自动故障切换。示例：别名 glm-4-flash 目标填 glm-4-flash, zhipu/glm-4-flash

网关设置

健康检查：定期拉一遍各渠道「免费模型列表」并测连通性（只读元数据，不消耗额度）。间隔越小越及时，也越费网络；保存即生效。
「模型主动探测」（给从没调用过的免费模型各发一次 1 token 请求，确认它不是摆设）与 「429 限流预判」（撞过一次 429 就记住当时用量，之后接近这个水位提前换路，而不是等被打回再冷却） 默认开启，无需设置，需要关就在 config.json 里把 probe_used_models / adaptive_preemption 设为 false。
能力档位是启发式估算（按模型名 + AA 榜分），**点模型页「特点」列里的档位 chip 就能手动改** （存进 config.json 的 model_tier_exact，点名优先，再点「自动」可撤销）； 也可以在 config.json 的 model_tiers 里用正则批量覆盖（优先级低于点名）。 route_strategy 只作为「显式写真实模型名时渠道排序」的兜底（auto-* 由模型名决定，见「网关用法」页）。

自动切换规则

            

              · 请求按「可用渠道 → 延迟从低到高」的顺序尝试，失败自动换下一个渠道重试；

              · 失败的「模型 × 渠道」组合进入冷却（时长按错误类型：连接失败短、限流/当天额度用完等冷却到明）；

              · 健康检查自动定期运行（间隔在「设置」页调整，默认 30 分钟）；

              · 响应头 X-Api-Hub-Channel 显示本次实际由哪个渠道服务（在「测试台」发一条消息，输出末尾就会写出渠道与延迟；命令行 curl -i 也能看到）；

              · 模型名填 auto-balanced / auto-quality /
                auto-stability / auto-speed /
                auto-vision 时，网关会自动选最优真实模型并跨模型无感切换
                （按「模型」页对应视图的排序逐个尝试，能用的排前面；auto-vision
                只挑能看图的模型，适合当 Hermes 的辅助视觉模型）。

              · 同一个会话里不会来回换模型：网关会认会话（客户端每轮都带完整历史，
                所以按第一条 user 消息识别），上一次成功产出的模型在这个会话里一直优先用，
                只有它失败或整个不可用才换 —— 想看当前粘在谁身上：
                GET /api/sticky；想立刻让它重新按策略选：
                DELETE /api/sticky（可加 ?strategy=quality
                只清一个视图）。会话闲置 2 小时自动失效。

              · 候选的第一顺位是会话粘性（本会话上次成功的模型），其次是收藏，
                然后才是策略分：「模型」页每个视图的 ★ 只管自己那一屏，
                视觉 视图的 ★ 是独立的一套（pinned_vision），
                只影响这一屏与 auto-vision 的切换顺序。
